Myth / fact

Four things people get wrong about LLMs

Each one costs somebody a bad architecture decision.

RNRon Northcutt@rlnorthcutt
Swipe
Myth one

“It searches the internet”

Myth

It looks things up when you ask.

  • Answers come from a live index
  • Facts are current by default
vs
Fact

It predicts from frozen weights.

  • Nothing is retrieved unless a tool does it
  • Its world ends at its training cutoff
@rlnorthcutt
2 / 8
Myth two

“It learns from our chats”

Myth

Correcting it today improves it tomorrow.

  • Feedback updates the model live
  • It remembers your preferences
vs
Fact

Weights are fixed at inference.

  • Memory is text replayed into context
  • Close the window and it is gone
@rlnorthcutt
3 / 8
Myth three

“A bigger window means better recall”

Myth

Paste everything and let it sort it out.

  • All tokens weigh the same
  • More context is always better
vs
Fact

Attention is finite and uneven.

  • The middle of a long context gets read least
  • Curation beats volume
@rlnorthcutt
4 / 8
Myth four

“Hallucination is a bug”

Myth

A good enough model will stop making things up.

  • It is a defect to be patched
  • Confidence tracks correctness
vs
Fact

It is the mechanism working as designed.

  • A plausible token is still a token
  • Grounding is your job, not its
@rlnorthcutt
5 / 8
The through-line

Every myth assumes a database.

It is a function. You supply the facts; it supplies the fluency.

@rlnorthcutt
6 / 8
So

What to change on Monday

  • Ground anything factual in a document you pasted
  • Treat memory as a feature you build, not one you get
  • Curate context instead of filling it
  • Wait for the next model to fix your pipeline
